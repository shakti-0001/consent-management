# Reviewed consent-management service (integration POC)

## What was changed from the uploaded ZIP
- Removed duplicate public-demo pending/decision/revocation routes.
- `/api/registry` and portal management routes use server-side WSO2 token introspection (`Authorization: Bearer ...`).
- Management identity uses the introspected username and OAuth `client_id` as its stable application key. It never trusts `application_id` from the request body.
- Runtime `/proxy/{api_id}/{api_version}/{operation_id}` continues to require the signed identity from a trusted server-side WSO2 adapter.
- Existing database models and generic operation registry are retained.

## Important limits (not a complete production integration)
1. You must configure and verify the real introspection endpoint and returned claim names for your WSO2 APIM 4.7.0.13 deployment.
2. Introspection does not always return user roles. If Publisher roles are absent, implement a trusted role lookup / adapter. Do not trust browser-supplied roles.
3. OAuth `client_id` is used as the application-specific key here. Ensure the trusted gateway adapter uses the same identifier for the grant lookup. If you require WSO2 application UUID, implement a trusted client_id-to-application UUID mapping.
4. Actual WSO2 subscription validation is NOT implemented in this code.
5. Automatic metadata synchronization for all published APIs is NOT implemented. Operations must be registered through the internal endpoint until a Publisher API synchronizer is added.
6. The Python proxy does not automatically intercept the normal `/student-verification/1.0.0/...` route. Configure a supported Classic Gateway mediation/extension or route protected calls through this proxy and prevent backend bypass.
7. Recursive key-name filtering is POC-only. Production must use response-schema field paths, and must explicitly handle error payloads, arrays, pagination, SOAP, streaming and binary content.
8. Do not use real Aadhaar/student data until gateway enforcement and authorization have been security-tested.

## Setup
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Edit .env with real server-side credentials/secrets
uvicorn app.main:app --host 127.0.0.1 --port 8100 --reload
```
Check `GET /health`, then configure the portal frontend to send the Bearer access token to the management endpoints. The service must be reachable only by trusted gateway/adapter processes, not directly from arbitrary clients.

## Portal endpoints
- `GET /api/registry`
- `POST /api/consent/requests`
- `GET /api/consent/requests/mine`
- `GET /api/consent/requests/pending`
- `POST /api/consent/requests/{request_id}/decision`
- `GET /api/consent/grants/mine`
- `POST /api/consent/grants/{grant_id}/revoke`

Management endpoints expect `Authorization: Bearer <WSO2 access token>` and perform server-to-server introspection. Publisher decision routes additionally require a role claim recognized by `PUBLISHER_ROLES` and ownership matching `publisher_subject`.

## Runtime proxy
- `/{proxy}/{api_id}/{api_version}/{operation_id}` as `/proxy/{api_id}/{api_version}/{operation_id}`
- Requires signed trusted identity headers generated by `gateway_signing_reference.py` only after WSO2 authentication.
- The gateway adapter must strip all incoming copies of the internal identity/signature headers and use server-validated identity.
